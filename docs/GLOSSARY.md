# Anote 术语小词典（GLOSSARY）—— 给非技术用户的解释

> 配合 docs/ADAPTERS.md 阅读。用生活类比解释本项目用到的计算机术语。

## 基础概念
| 术语 | 生活类比 | 说明 |
|------|----------|------|
| 软件本体 | 一栋房子 | 应用本身（Zotero/Obsidian/Anote） |
| 插件 | 按插座规格造的电器 | 装在软件里扩展功能的模块（Better BibTeX、Dataview） |
| 运行时/宿主 | 房子（供电+线路） | 插件运行所依赖的环境 |
| API | 插座规格 | 软件对外开放的接口，插件靠它工作 |
| 协议 | USB 国家标准 | 大家共同遵守的通用接口标准 |
| 服务器 | 提供服务的商店 | 提供功能的程序 |
| 客户端 | 顾客 | 使用功能的程序 |

## 为什么插件不能跨软件用
- 插件 = 按"某个软件的插座规格"制造 → 插到别的软件（插座不同）就插不进去
- 强行移植 = 重写那个软件 → 工作量巨大且无法追上原版

## 两类兼容路径
| 路径 | 类比 | 含义 |
|------|------|------|
| A 协议直连 | 统一 USB 口 | 插件按标准造 → Anote 直接使用，零转接 |
| B 宿主转接 | 旅行转换插头 | 插件留在原宿主（功能 100% 保留），Anote 用 Adapter（翻译官）连接 |

## 标准协议（路径 A 的对象）
| 术语 | 类比 | 说明 |
|------|------|------|
| MCP | 蓝牙 | 让不同 AI 工具互相调用能力的标准 |
| LSP | USB 鼠标 | 编辑器通用的"语言服务"标准（补全/检查） |
| BibTeX/CSL | .docx | 引文与样式文件的标准格式 |
| JSON-RPC/HTTP | 普通话+电话 | 程序间远程通信的通用方式 |

## Adapter（路径 B）四动作
| 动作 | 生活类比 | 含义 |
|------|----------|------|
| detect | 体检 | 检查宿主是否可用、能否连接 |
| pull | 进货 | 把宿主产出导入 Anote |
| push | 出货 | 把 Anote 数据送进宿主 |
| call | 遥控 | 让宿主执行 Anote 要求的操作 |

## 其他常用词
| 术语 | 说明 |
|------|------|
| 导入/导出 | 把数据搬进来 / 送出去 |
| 转接器（Adapter） | 连接两个不同规格系统的翻译官程序 |
| 注册表 | 记录"装了哪些插件/宿主"的清单文件 |
| 标准格式 | 任何软件都能读写的格式（MD/TEX/BibTeX/PDF） |
| 薄壳原则 | 界面只做展示，逻辑集中在服务层（Anote 的设计铁律） |
