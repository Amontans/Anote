# 架构文档（ARCHITECTURE）

## 设计原则

1. **单一真相源**：`src/` 的笔记是唯一不可再生数据；其余（索引/语义缓存/回顾/队列）全部可重建
2. **资产不绑定工具**：一切知识是 `.tex`/`.bib`/PDF 纯文本；编辑器、AI、Web 外壳都是可替换的
3. **AI 可插拔**：AI 层只做"提议与草拟"，人做"确认"；换模型/助手不损失任何资产
4. **自动化 > 手动**：能由钩子/定时器/脚本做的，绝不要求人做
5. **接口先于实现**：所有数据格式与 CLI 有书面契约（`docs/INTERFACES.md`），扩展不需读代码

## 分层结构

```
┌────────────────────────────────────────────────┐
│  AI 层（可插拔）                                  │
│  Pi + DeepSeek：检索/精读填充/提炼/问答/回顾       │
├────────────────────────────────────────────────┤
│  命令层（唯一入口）                               │
│  manage.sh  →  11 个命令                        │
├────────────────────────────────────────────────┤
│  脚本层（纯函数，单一职责，~100-300 行）           │
│  search/ask/embed/index-gen/check/review/…     │
├────────────────────────────────────────────────┤
│  数据层（纯文本，git 版本化）                     │
│  src/ memory/ books/ projects/ queue/roadmap   │
└────────────────────────────────────────────────┘
```

## 数据流（三级管线）

```
① 积累:  检索(--queue) → 下载(--tex-note) → src/papers/精读笔记 → src/学科笔记
         ▲                                      │
         └── ask.py(关键词/语义) ← .semantic/ ←──┘  （问答即读即答）
② 编译:  周回顾(review.py) → 提炼 → memory/{insights,concepts,open-questions}
③ 成书:  anote book/chapter → books/<名>/ → latexmk 编译 PDF
└── 全程: pre-commit 自动索引+自检；git 提交；backup 推送
```

## 状态流（队列）

`📥待读 → 📖在读 → ✅已精读 → 🗄已归档`（+ check.py 一致性校验）

## 关键机制

| 机制 | 实现 | 目的 |
|------|------|------|
| 防遗忘 | check.py 6 项 + pre-commit 提示 | 结构不腐烂 |
| 省 token | ask.py 片段检索（grep/语义） | 问答不读全文 |
| 升级安全 | schema_version + 可重建派生物 | 换组件不换数据 |
| 备份 | git + `anote backup` | 资产永不丢失 |
